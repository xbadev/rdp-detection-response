# Phase 02 — Controlled Exposure (ICMP)

Enabled inbound ICMP from a single source (Kali) before exposing any real services. The purpose is to validate that Windows Firewall actually enforces source-level restrictions — that turning a rule on for one IP doesn't accidentally turn it on for everyone — before we risk that assumption with RDP in Phase 03.

## Environment

| System | Role | IP |
|---|---|---|
| Kali | Authorized source | `10.10.10.30` |
| Windows Server 2025 | Target | `10.10.10.40` |
| Ubuntu (SSH lab) | Unauthorized source | `10.10.10.20` |

Starting state: Phase 01 confirmed all inbound traffic is blocked by default.

## Steps

### 1. Enable + scope the ICMP rule

```powershell
# Enable the existing ICMPv4-In rule under File and Printer Sharing.
$rule = Get-NetFirewallRule -DisplayGroup 'File and Printer Sharing' |
    Where-Object DisplayName -like '*Echo Request - ICMPv4-In*'

$rule | Enable-NetFirewallRule

# Restrict to Kali only — single source, no ranges, no subnet.
$rule | Set-NetFirewallRule -RemoteAddress '10.10.10.30'
```

### 2. Test from authorized source

From Kali:

```bash
ping -c 3 10.10.10.40
```

Expected: replies received.

### 3. Test from unauthorized source

From any other host on `10.10.10.0/24` (e.g. Ubuntu at `10.10.10.20`, or another VM you spin up briefly):

```bash
ping -c 3 10.10.10.40
```

Expected: no replies. The rule is enabled but scoped — non-Kali sources are still blocked.

## Findings

| Source | Expected | Observed |
|---|---|---|
| Kali (`10.10.10.30`) | Allowed | ✅ replies |
| Other internal hosts | Blocked | ✅ no replies |

Source-scoping works. We can now expose a real service in Phase 03 with confidence that scoping it to Kali means scoping it *only* to Kali.

## Why this phase exists

It's tempting to skip straight to RDP exposure — that's where the interesting attacks happen. The reason this phase is here: source-scoping is the difference between "RDP is open to my one trusted attacker IP for testing" and "RDP is open to the internet because the firewall rule was permissive." Validating it at the ICMP layer (which is harmless) means a misconfiguration won't be discovered later when it's protecting RDP credentials.

## Cleanup before Phase 03

You can leave the ICMP rule scoped to Kali — it doesn't conflict with RDP. Or revert:

```powershell
$rule | Disable-NetFirewallRule
$rule | Set-NetFirewallRule -RemoteAddress 'Any'   # restore default scope
```
